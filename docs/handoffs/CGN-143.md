## What changed

- Added an Evidence-owned application API for private manual evidence create, claim update and archive. Ownership comes from a server-resolved Identity authorization context; request bodies cannot select an owner.
- Create requires an idempotency key. Replays return the existing active record; reuse with changed content conflicts. Updates and archives require the expected revision, and update only changes claim text.
- Attached objects require a same-owner, same-key clean validation result. The repository persists the immutable object revision, checksum, content type, measured size and validation time.
- Archive removes a record from active reads and returns only a tombstone. Migration 002 adds revision/idempotency/validation fields and an Evidence-owned audit table and trigger. Audit entries exclude claims and object keys.
- Updated the contract registry, module index, current-state entry, known-risk note and service README.

## Known limitations

- This exports a service application API; no public HTTP listener or controller exists. The owning transport must authenticate callers and supply a server-resolved Identity context.
- The validator is an injected port to CGN-134/142 behavior. This change does not deploy a production scanner, compose storage credentials or validate deployed object retention/backups.
- Evidence records remain private and unverified. Expert validation and confidence transitions remain with Experts; no cross-domain event is emitted.

## Rollback notes

The migration is additive and has no automatic down migration. To roll back application behavior, revert/disable the API while retaining revision, validation and audit data. Do not drop the audit table or evidence columns without a separately reviewed backup and data-retention plan.
