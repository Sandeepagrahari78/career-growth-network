## What changed

Added the versioned Evidence upload-validation contract and its configured
policy. The policy allows PDF, JPEG and PNG, caps uploads at 10 MiB, sets
upload/download URL TTLs to 300/60 seconds, requires server-side owner checks,
private objects, post-upload validation and quarantine until a clean scan.

Added provider-neutral Evidence helpers for upload authorization, actual
object validation and download authorization. Post-upload inspection checks
the authoritative owner, stored MIME, measured byte count, file extension and
signature, private/quarantined state, immutable object revision and SHA-256.
Only a clean malware verdict returns `validated`; scanner absence, unavailability,
error, timeout or suspicious content fails closed. The helper returns expiry
and authorization results, never a signed URL, and does not release an object.

Schema. The service configuration contains the approved types, size and URL
lifetimes. Security invariants require private objects, server owner
authorization, post-upload validation and fail-closed scanner behavior. The
validation result pins the exact object revision and checksum that passed scan.

## Known limitations / risks

- CGN-134 provides the contract and reusable hooks only. It does not create a
  storage provider, scanner integration, URL signer, route, quarantine state
  store or release transition. The adapter must keep storage private and
  quarantined, use authoritative ownership metadata and pin the scanned
  revision/checksum for any later download.
- `scanTimeoutMs` is required from consumer configuration; no scanner timeout
  value was specified in the approved policy, so this ticket does not invent
  one.
- Staging validation against SeaweedFS belongs to CGN-142 after this contract
  merges. Do not claim a storage workflow is active from these unit tests.
- TypeScript build/typecheck and Linux CI have not yet passed on this branch.
