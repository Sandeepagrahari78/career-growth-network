## Why
Evidence before the change:
- https://github.com/Sandeepagrahari78/career-growth-network/actions/runs/39674424444 : PR CI wall-clock about 4m03s. The quality job used 99 seconds and the slowest Docker job, which waited for quality, used 128 seconds. Docker, integration, E2E and performance each check out their own source and do not consume quality or security job artifacts.
- https://github.com/Sandeepagrahari78/career-growth-network/actions/runs/39671771873 : Main CI about 3m38s.
- https://github.com/Sandeepagrahari78/career-growth-network/actions/runs/39672291241 : exact-candidate staging validation about 33s.
- These runs come from different commits/events; their sum is a planning estimate, **not** observed single-Jira-ticket time.

## Exact files changed
- `.github/workflows/pr-ci.yml`: allow Docker, integration stack, E2E, performance smoke and PostgreSQL jobs to start after changed-path detection, independently of `quality` and `security` jobs. Preserve the original `changes` outputs/if conditions, job commands, security scans and all `gate` success/skip assertions.
- `docs/handoffs/CGN-302.md`: this report.

## Contracts/events/migrations and security
- No API, DB schema, event, application behavior, product, permission or auth changes.
- No scanners or tests were deleted. No weakening of fail-closed aggregate PR gate, review, Main CI, staging or Jira delivery sync.
- Trade-off: when quality fails, already-running parallel Docker/integration jobs may use extra GitHub runner minutes. Failed checks must still fail the aggregate gate.
- Critical production or security changes require full original checks; this ticket only reorders independent jobs.

5. Check latest Main CI, candidate staging and Jira Delivery Sync **after reviewed merge**.

As of handoff creation, neither an exact-head PR CI run nor the 7–10 minute end-to-end goal has been validated; do not present them as passed.
