## What changed

Identity now stores one membership state per account and opaque organization UUID (`pending`, `approved`, or `revoked`) and records state changes in an audit table. A new authenticated Identity context lookup derives the account from the HttpOnly session, scopes membership to the requested organization, and returns the recruiter role only when membership is approved and the global recruiter role is active. It rejects missing, duplicate, malformed, or additional query parameters; caller-supplied roles/statuses are not accepted.

The response is informational context, not a bearer credential or proof of Gateway identity. Recruiter retains organization onboarding and approval ownership. No public membership-write route was added because a trusted write workflow and service-authentication contract are not established here; the Identity repository method is internal to Identity.

Added the TypeScript and JSON Schema `cgn.identity.organization-authorization-context.v1` and exported its TypeScript type from `packages/contracts`. It is served from `GET /v1/identity/auth/organization-authorization-context?organizationId=...`. The response includes one organization membership state and the recruiter role only when membership is approved and the global recruiter role is active. Updated the engineering contract registry and known-risks note. The contract is not authorization proof when forwarded by a client.
