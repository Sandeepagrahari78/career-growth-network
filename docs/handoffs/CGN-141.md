## What changed

Added the Evidence service's initial private evidence record schema and an
owner-scoped repository. Records distinguish manual claims from observed
source references, default to `unverified`, and accept only private visibility.
Private object references are opaque keys rather than bucket URLs. Active reads
and archival updates require the owning Identity subject. No API, event, or
confidence transition workflow was added.

## Database / migration / config changes

Added `evidence_records` migration for the Evidence-owned `cgn_evidence`
database. The schema stores an opaque `owner_id` without a cross-service
foreign key, enforces provenance payload consistency, defaults verification to
`unverified`, constrains visibility to `private`, rejects URL-shaped object
keys, and indexes active records by owner and creation time. Migration file
changes now trigger PostgreSQL CI validation.

## Known limitations / risks

- The repository currently provides the schema and query boundary, not a
  PostgreSQL client adapter, HTTP API, authorization middleware, or object-store
  integration. Those require their owning follow-up tickets.
- Local PostgreSQL integration could not run without Docker; merge readiness
  depends on the PostgreSQL CI job passing.
- `verified` is stored as a state only. Authorized verification transitions and
  confidence semantics remain with their owning tickets/workflows.
